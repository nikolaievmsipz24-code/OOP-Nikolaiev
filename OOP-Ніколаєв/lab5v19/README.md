## 📌 Короткий опис виконаної роботи
У межах цієї лабораторної роботи було створено ієрархію класів для обробки та виведення системних логів (журналів) із застосуванням принципів об'єктно-орієнтованого програмування, а саме **поліморфізму** та **динамічного зв’язування**:
1. **Базовий клас `LogEntry`**: Містить загальні поля (`Timestamp`, `Message`), конструктор та віртуальний метод `Display()`.
2. **Похідні класи (`InfoLog`, `WarningLog`, `ErrorLog`)**: Наслідують базовий клас, додають власні унікальні поля (`Source`, `Severity`, `ExceptionType`) та за допомогою модифікатора `override` реалізують власний поліморфний вивід інформації з різним кольоровим оформленням консолі.
3. **Колекція базового типу та поліморфізм**: У методі `Main` створено єдиний список `List<LogEntry>`, до якого додано екземпляри всіх похідних класів. У циклі викликається метод `Display()`, завдяки чому для кожного об'єкта автоматично виконується його власна реалізація.
4. **Агрегація результатів**: За допомогою засобів LINQ та властивостей об’єктів виконано підрахунок загальної кількості записів, кількості елементів кожного типу, а також знайдено максимальний рівень важливості серед попереджень (`Max Severity`).

Відповіді на контрольні запитання
1. Що таке поліморфізм і як він реалізується в C# за допомогою virtual та override?

Поліморфізм — це один із фундаментальних принципів об'єктно-орієнтованого програмування, який дозволяє об’єктам різних похідних класів реагувати на однаковий виклик методу по-різному, залежно від їхнього фактичного типу під час виконання.

В C# поліморфізм реалізується за допомогою парних модифікаторів:

virtual: додається до оголошення методу в базовому класі. Це сигналізує компілятору, що даний метод може бути перевизначений у похідних класах.

override: додається до методу в похідному класі. Вказує на те, що цей метод надає нову, унікальну реалізацію віртуального методу базового класу.

2. Поясніть поняття динамічного зв’язування. Чим воно відрізняється від статичного?

Динамічне зв’язування (пізнє зв’язування) — це процес, за якого визначення того, яка саме реалізація методу буде викликана, відбувається під час виконання програми (Runtime), а не під час компіляції. Вибір методу залежить від фактичного типу об'єкта в пам'яті, а не від типу змінної-посилання.

Основні відмінності:

Статичне зв’язування (раннє): виконується на етапі компіляції (Compile time). Застосовується для звичайних (невіртуальних) методів, перевантажених методів та static-методів. Швидше за виконанням, але менш гнучке.

Динамічне зв’язування (пізнє): виконується під час роботи програми (Runtime) за допомогою таблиці віртуальних методів (VMT). Застосовується для virtual / override методів та інтерфейсів. Забезпечує гнучкість та розширюваність коду.

3. Наведіть приклад, як поліморфізм дозволяє писати більш гнучкий та розширюваний код.

Поліморфізм дозволяє писати код, який працює із загальними абстракціями (базовими класами), не прив'язуючись до конкретних реалізацій.

Приклад:
У нашій лабораторній роботі метод обробки списку працює з колекцією List<LogEntry> і викликає log.Display() у циклі.

Якщо в майбутньому знадобиться додати новий тип логу — наприклад, AuditLog або DatabaseLog:

Ми просто створюємо новий клас, який успадковує LogEntry та перевизначає метод Display().

Нам не потрібно змінювати існуючий код обробки списку, циклу чи агрегації у Main.
Програма автоматично почне працювати з новим типом логу. Це відповідає принципу Open/Closed (код відкритий для розширення, але закритий для модифікації).

4. Які переваги дає використання колекцій базових типів для роботи з поліморфними об’єктами?

Використання колекцій базового типу (наприклад, List<LogEntry>) надає такі переваги:

Однорідне збереження різнорідних об'єктів: Дозволяє зберігати об'єкти різних похідних класів (InfoLog, WarningLog, ErrorLog) у єдиному масиві чи списку.

Спрощення обробки даних: Зникає потреба створювати окремі масиви чи списки під кожен тип і дублювати однакові цикли обробки.

Абстрагування від деталей: Код, який обробляє колекцію, оперує лише інтерфейсом базового класу, що зменшує зв'язаність коду (low coupling).
