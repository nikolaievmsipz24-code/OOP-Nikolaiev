# Звіт до самостійної роботи №15 (`iw15`)

**Тема:** Делегати й лямбда-вирази: власні утиліти для колекцій.  
**Клас:** `CollectionUtils` (`Map`, `MaxBy`, `Filter`, `ForEach`).

---

## Висновок

У самостійній роботі реалізовано статичний узагальнений клас `CollectionUtils` з методами `Map`, `MaxBy`, `Filter` та `ForEach` на базі делегатів `Func`, `Predicate` і `Action` і продемонстровано їх роботу з лямбда-виразами на трьох різних колекціях (`List<Product>`, `List<int>`, `List<string>`). Використання делегатів у поєднанні з узагальненнями дає змогу передавати поведінку в універсальні алгоритми обходу колекцій без дублювання коду, а лямбда-вирази роблять виклики лаконічними та читабельними. Порівняно з вбудованими операторами LINQ (`Select`, `Where`, `MaxBy`), власні утиліти дозволяють чітко контролювати хід виконання та одразу повертати сформовані списки, тоді як LINQ краще підходить для ланцюжків лінивих запитів.

---

## Контрольні запитання та відповіді

### 1. Чому делегати є зручним механізмом для передавання поведінки в узагальнені методи?
Делегати описують сигнатуру методу (вхідні параметри та тип результату) окремо від конкретної реалізації. Разом з узагальненими параметрами типів (`<T>`, `<TSource, TResult>`, `<TKey>`) це дозволяє писати типобезпечні та гнучкі алгоритми для будь-яких колекцій, підставляючи потрібну логіку через `Func`, `Predicate` чи `Action` без копіювання циклів.

### 2. У чому різниця між `Func<T, TResult>`, `Action<T>` та `Predicate<T>`?
* **`Func<T, TResult>`** — приймає аргумент (або кілька аргументів) і **повертає** значення типу `TResult` (наприклад, перетворення елемента або вибір ключа для порівняння).
* **`Action<T>`** — приймає аргумент і **нічого не повертає** (`void`); використовується для дій з побічними ефектами (вивід у консоль, логування, модифікація стану).
* **`Predicate<T>`** — приймає аргумент і **повертає `bool`** (`true` або `false`); призначений для перевірки умови та фільтрації елементів.

### 3. Які переваги дає поєднання generic-методів і лямбда-виразів під час роботи з колекціями?
Generic-методи забезпечують повторне використання коду та строгу типізацію для різних типів даних (`int`, `string`, `Product`) без `boxing`/`unboxing` і зайвого приведення типів, а лямбда-вирази дозволяють коротко описувати потрібну умову чи перетворення прямо в місці виклику без створення зайвих допоміжних методів.

### 4. У яких випадках власні утиліти на кшталт `Map` чи `Filter` корисно реалізувати самостійно, навіть якщо існує LINQ?
Власні утиліти корисно писати для кращого розуміння роботи делегатів і механізмів обробки колекцій, а також у проєктах, де потрібна специфічна поведінка — наприклад, одразу отримати матеріалізований `List<T>`, додати власне логування/перевірки аргументів або контролювати виділення пам'яті під конкретні вимоги.
